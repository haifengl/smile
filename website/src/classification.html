Classification

The smile.classification package is a complete suite of supervised classifiers for labelling new instances with one of a discrete set of class labels. Every algorithm exposes static fit(…) factories (no mutable builders to misconfigure), accepts arbitrary integer labels, implements Classifier<T>, and is serializable.

This page walks the core abstractions (including nested Options / Properties hyperparameters), a shared 2-D visualization helper, an algorithm selection guide, then each family of methods with runnable Java / Scala / Kotlin playgrounds. Expected outputs cite unit-test metrics where available; plot demos open a Swing window.

Core Abstractions

Classifier<T> is the central contract: hard prediction (predict(x)), optional soft prediction (predict(x, posteriori)), raw score (score), and optional online update (update). Probe capabilities with isSoft() and isOnline() before calling the corresponding methods — both default to false.

{% include "components/playground-extra-actions.njk" %} 
// Works for any smile.classification.Classifier<T>
int label = model.predict(sample);

if (model.isSoft()) {
    double[] posteriori = new double[model.numClasses()];
    model.predict(sample, posteriori); // class probabilities
}

if (model.isOnline()) {
    model.update(newSample, newLabel); // incremental learning
}

label / optionally filled posteriori

DataFrameClassifier

Tree ensembles and related models implement DataFrameClassifier (extends Classifier<Tuple>). They train with a Formula plus a DataFrame, then predict named-column rows. DataFrameClassifier.of(formula, classifier) wraps any Classifier<double[]> so formula feature extraction is applied automatically.

ClassLabels

Labels need not be contiguous or zero-based — {-1,+1} or {3,7,14} all work. Internally, ClassLabels remaps them to [0, k); predict always returns the original label values. ClassLabels.fit(y) also exposes priors and per-class counts.

{% include "components/playground-extra-actions.njk" %} 
import smile.classification.*

int[] y = {-1, +1, -1, +1};
LogisticRegression model = LogisticRegression.fit(x, y);
int label = model.predict(sample);   // returns -1 or +1

ClassLabels codec = ClassLabels.fit(y);
codec.k;       // 2
codec.priori;  // estimated class priors

Options and Properties

Most algorithms expose a nested Options record for strongly typed hyperparameters (for example RandomForest.Options, SVM.Options, LogisticRegression.Options). Construct an Options instance and pass it to fit, or load the same knobs from a configuration file via java.util.Properties. Each Options type supports toProperties() and Options.of(props) for round-trips. Property keys use underscores (e.g. smile.random_forest.trees); algorithm sections below list the field name and the corresponding full property key in a description list.

{% include "components/playground-extra-actions.njk" %} 
import java.util.Properties
import smile.classification.RandomForest
import smile.data.formula.Formula

// Strongly typed Options
var options = new RandomForest.Options(200)
RandomForest model = RandomForest.fit(formula, data, options)

// Or configuration-file style Properties
Properties params = new Properties()
params.setProperty("smile.random_forest.trees", "200")
params.setProperty("smile.random_forest.max_depth", "10")
model = RandomForest.fit(formula, data, params)

// Round-trip
Properties props = options.toProperties()
var again = RandomForest.Options.of(props)

The shared visualize helper paints a dense prediction grid, overlays a subsample of training points, and (for binary models) draws the 0.5 contour. 2-D demos below call this helper after fitting.

{% include "components/playground-extra-actions.njk" %} 
import smile.classification.Classifier;
import smile.math.MathEx;
import smile.plot.swing.*;

Figure visualize(Classifier<double[]> model, double[][] x, int[] y) {
    double[] lower = MathEx.colMin(x);
    double[] upper = MathEx.colMax(x);
    double[] step = { (upper[0]-lower[0])/50, (upper[1]-lower[1])/50 };
    lower[0] -= 4*step[0]; lower[1] -= 4*step[1];
    upper[0] += 4*step[0]; upper[1] += 4*step[1];

    int nx = (int) Math.round((upper[0]-lower[0])/step[0]) + 1;
    int ny = (int) Math.round((upper[1]-lower[1])/step[1]) + 1;
    double[] gx = new double[nx];
    double[] gy = new double[ny];
    for (int i = 0; i < nx; i++) gx[i] = lower[0] + i * step[0];
    for (int j = 0; j < ny; j++) gy[j] = lower[1] + j * step[1];

    double[][] grid = new double[nx*ny][2];
    for (int i = 0, k = 0; i < nx; i++)
        for (int j = 0; j < ny; j++, k++) {
            grid[k][0] = gx[i];
            grid[k][1] = gy[j];
        }
    int[] pred = model.predict(grid);
    double[][] z = new double[ny][nx];
    for (int i = 0, k = 0; i < nx; i++)
        for (int j = 0; j < ny; j++, k++)
            z[j][i] = pred[k];

    // Subsample training points for overlay clarity
    int n = Math.min(x.length, 2000);
    double[][] xs = java.util.Arrays.copyOf(x, n);
    int[] ys = java.util.Arrays.copyOf(y, n);

    var figure = ScatterPlot.of(grid, pred, '.').figure();
    figure.add(ScatterPlot.of(xs, ys, 'o'));
    if (model.numClasses() == 2)
        figure.add(new Contour(gx, gy, z, new double[]{0.5}));
    return figure;
}

import smile.classification.Classifier
import smile.math.MathEx
import smile.plot.swing._

def visualize(model: Classifier[Array[Double]], x: Array[Array[Double]], y: Array[Int]): Figure = {
  val lower = MathEx.colMin(x)
  val upper = MathEx.colMax(x)
  val step = Array((upper(0) - lower(0)) / 50, (upper(1) - lower(1)) / 50)
  lower(0) -= 4 * step(0); lower(1) -= 4 * step(1)
  upper(0) += 4 * step(0); upper(1) += 4 * step(1)

  val nx = Math.round((upper(0) - lower(0)) / step(0)).toInt + 1
  val ny = Math.round((upper(1) - lower(1)) / step(1)).toInt + 1
  val gx = Array.tabulate(nx)(i => lower(0) + i * step(0))
  val gy = Array.tabulate(ny)(j => lower(1) + j * step(1))

  val grid = Array.tabulate(nx * ny) { k =>
    val i = k / ny; val j = k % ny
    Array(gx(i), gy(j))
  }
  val pred = model.predict(grid)
  val z = Array.ofDim[Double](ny, nx)
  var k = 0
  for (i <- 0 until nx; j <- 0 until ny) {
    z(j)(i) = pred(k); k += 1
  }

  val n = math.min(x.length, 2000)
  val xs = x.take(n)
  val ys = y.take(n)

  val figure = ScatterPlot.of(grid, pred, '.').figure()
  figure.add(ScatterPlot.of(xs, ys, 'o'))
  if (model.numClasses == 2)
    figure.add(new Contour(gx, gy, z, Array(0.5)))
  figure
}

    val lower = MathEx.colMin(x)
    val upper = MathEx.colMax(x)
    val step = doubleArrayOf((upper[0] - lower[0]) / 50, (upper[1] - lower[1]) / 50)
    lower[0] -= 4 * step[0]; lower[1] -= 4 * step[1]
    upper[0] += 4 * step[0]; upper[1] += 4 * step[1]

    val nx = Math.round((upper[0] - lower[0]) / step[0]).toInt() + 1
    val ny = Math.round((upper[1] - lower[1]) / step[1]).toInt() + 1
    val gx = DoubleArray(nx) { i -> lower[0] + i * step[0] }
    val gy = DoubleArray(ny) { j -> lower[1] + j * step[1] }

    val grid = Array(nx * ny) { k ->
        val i = k / ny; val j = k % ny
        doubleArrayOf(gx[i], gy[j])
    }
    val pred = model.predict(grid)
    val z = Array(ny) { DoubleArray(nx) }
    var k = 0
    for (i in 0 until nx) for (j in 0 until ny) {

    val n = minOf(x.size, 2000)
    val xs = x.copyOf(n)
    val ys = y.copyOf(n)

    val figure = ScatterPlot.of(grid, pred, '.').figure()
    figure.add(ScatterPlot.of(xs, ys, 'o'))
    if (model.numClasses() == 2)
        figure.add(Contour(gx, gy, z, doubleArrayOf(0.5)))
    return figure
}

Algorithm Selection Guide

There is no universally best classifier. Use this table as a starting point.

SituationRecommendedNotes
Strong default baselineRandomForestRobust mixed tabular features; free OOB error.
Highest tuned tabular accuracyGradientTreeBoostUsually strongest after tuning shrinkage / trees.
Fast, interpretableDecisionTree, LogisticRegressionExplainability and quick diagnostics.
High-dim sparse textDiscreteNaiveBayes, SparseLogisticRegression, MaxentCount / sparse feature spaces.
p > nFLD, SparseLogisticRegressionAvoid plain LDA/QDA (singular covariance).
Gaussian, similar covariancesLDAFast linear soft classifier.
Different class spreadsQDA / RDARDA blends LDA↔QDA via alpha.
Nonlinear, moderate nSVM (Gaussian), RBFNetwork, MLPScale features first.
Streaming / onlineDiscreteNaiveBayes, LogisticRegression, MLPCheck isOnline().

K-Nearest Neighbors

k-NN classifies by majority vote among the k nearest training points (lazy / instance-based learning). SMILE picks a KD-tree for low-dimensional dense Euclidean data, a cover tree for higher-dimensional metric spaces, or linear search for arbitrary distances. Soft posteriors are the fraction of neighbors per class. Normalize features before use — distance methods are scale-sensitive.

On Iris, LOOCV accuracy is about 0.96 for 1-NN and 3-NN, and 0.9667 for 5-NN / 7-NN (unit tests). Larger k smooths the boundary but can blur class edges; odd k helps avoid ties in binary problems.

{% include "components/playground-extra-actions.njk" %} 
import smile.classification.KNN
import smile.datasets.Iris
import smile.validation.LOOCV

var iris = new Iris()
LOOCV.classification(iris.x(), iris.y(), (x, y) -> KNN.fit(x, y, 3))

Linear Discriminant Analysis

LDA assumes class-conditional Gaussians that share a pooled covariance (homoscedastic). The decision boundary is linear. It is fast and soft (isSoft() == true). Features with variance below tol (default 1e-4) are dropped. LDA fails when p > n (singular pooled covariance) — use FLD or RDA instead.

Iris LOOCV accuracy in the unit tests is 0.8533 — lower than k-NN on this set because the Gaussian / shared-covariance assumptions are imperfect for Iris. On many near-Gaussian problems LDA remains an excellent linear baseline.

import smile.datasets.Iris
import smile.validation.LOOCV

Fisher's Linear Discriminant

FLD finds a projection that maximizes between-class scatter relative to within-class scatter, then classifies by nearest projected class mean. Unlike LDA it does not require equal covariances or Gaussian classes. When n < p it uses SVD, making it the go-to linear method for the small-sample regime. Parameter L (default k − 1) is the number of discriminant directions; at most min(p, k−1) are meaningful. Soft prediction is not supported.

Iris LOOCV accuracy is about 0.98 in the unit tests.

{% include "components/playground-extra-actions.njk" %}

import smile.datasets.Iris
import smile.validation.LOOCV

var iris = new Iris()

Quadratic Discriminant Analysis

Naive Bayes

General Naive Bayes accepts arbitrary Distribution objects for each (class, feature) pair — any distribution from smile.stat.distribution. Soft prediction uses a log-sum-exp trick; online update is not supported. On Iris with 3-component Gaussian mixtures per feature, LOOCV accuracy is about 0.9533.

{% include "components/playground-extra-actions.njk" %} 
import java.util.stream.IntStream
import smile.classification.NaiveBayes
import smile.datasets.Iris
import smile.math.MathEx
import smile.stat.distribution.*

var iris = new Iris()
double[][] data = iris.x()
int[] label = iris.y()
int p = data[0].length, k = MathEx.max(label) + 1

double[] priori = new double[k]
Distribution[][] condprob = new Distribution[k][p]
for (int i = 0; i < k; i++) {
    priori[i] = 1.0 / k
    final int c = i
    for (int j = 0; j < p; j++) {
        final int f = j
        double[] xi = IntStream.range(0, data.length)
            .filter(l -> label[l] == c).mapToDouble(l -> data[l][f]).toArray()
        condprob[i][j] = GaussianMixture.fit(3, xi)
    }
}
var model = new NaiveBayes(priori, condprob)
model.predict(data[0])

One-Versus-Rest and One-Versus-One

Both strategies reduce a k-class problem to binary trainers (k ≥ 3). OvR trains k classifiers (class i vs rest) and picks the highest Platt-scaled score — the base trainer should support score() or soft prediction will be unavailable. OvO trains k(k−1)/2 pairwise classifiers; hard prediction always works via majority vote. Prefer OvO for SVMs; OvR for calibrated soft models like logistic regression.

{% include "components/playground-extra-actions.njk" %} 
import smile.classification.*
import smile.math.kernel.GaussianKernel

// OvR with logistic regression
OneVersusRest<double[]> ovr = OneVersusRest.fit(x, y,
    (a, b) -> LogisticRegression.fit(a, b));

// OvO with SVM (+1/-1 binary labels inside)
OneVersusOne<double[]> ovo = OneVersusOne.fit(x, y,
    (a, b) -> SVM.fit(a, b, new GaussianKernel(1.0), new SVM.Options(1.0)));

int label = ovo.predict(sample);  // voting always works
if (ovr.isSoft()) {
    double[] post = new double[ovr.numClasses()];
    ovr.predict(sample, post);
}

Random Forest

An ensemble of trees grown on bootstrap samples with random feature subsets at each split. Majority vote (optionally OOB-weighted) gives the prediction. OOB samples yield a nearly free unbiased accuracy estimate via model.metrics(). Iris LOOCV with a modest forest is about 0.9533.

Gradient Tree Boost

Gradient boosting fits regression trees to pseudo-residuals. Shrinkage (learning rate) trades off against tree count: smaller shrinkage needs more trees but usually generalizes better. Stochastic subsampling (subsample < 1) adds regularization. Often the strongest tabular accuracy after tuning.

Hyperparameters are fields of the nested GradientTreeBoost.Options record. Pass an Options instance to fit, or a java.util.Properties map using the keys below (Options.toProperties() / Options.of(props) round-trip).

Boosting rounds (default 500).
maxDepth
smile.gradient_boost.max_depth

maxNodes
smile.gradient_boost.max_nodes
Max leaf nodes (default 6).
nodeSize
smile.gradient_boost.node_size
Minimum leaf size (default 5).

AdaBoost

Adaptive boosting iteratively reweights misclassified samples (SAMME for multiclass). Sensitive to label noise and outliers because hard examples keep gaining weight, but often less overfit-prone than a single deep tree. Iris LOOCV accuracy is about 0.9533.

Practical Tips

  • Probe capabilities. Call isSoft() / isOnline() before soft predict or update.
  • Arbitrary labels. Any integers work; predict returns original values.
  • Validation. Prefer CrossValidation.classification or LOOCV.classification (and Accuracy) over hand-rolled holdouts; seed with MathEx.setSeed(…) for reproducible ensembles and folds.
  • Formula vs arrays. Use Formula + DataFrame for mixed/categorical tabular data (trees, ensembles); use double[][] for numeric feature matrices and distance / kernel methods.
  • Class imbalance. See smile.classification.resampling (SMOTE, ADASYN, Tomek links, …) before tuning the classifier.
  • Scale-sensitive models. Normalize for LDA/QDA/RDA/FLD, logistic, k-NN, SVM, MLP, RBF. Trees and DiscreteNaiveBayes are scale-invariant.
  • Serialize. Write.object(model, path) / Read.object(path).
  • Properties configs. Prefer nested Options when coding; use the property keys listed under each algorithm (underscores, e.g. smile.random_forest.trees) for configuration files. Round-trip with toProperties() / Options.of(props).
  • Large n. Prefer tree ensembles; kernel SVM scales poorly. For p > n, prefer FLD / sparse logistic / Maxent.
  • Calibration. Platt or isotonic on a held-out set when you need trustworthy probabilities from score-based models.
