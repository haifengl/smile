SMILE Serve

SMILE Serve is a production-ready inference server built on Quarkus. It exposes three complementary inference capabilities on the JVM through a unified REST API and bundles a React web UI in the same process.

Capability API prefix Description
Classic ML /api/v1/ml/models Serialized SMILE models (.sml) — classifiers and regressors
ONNX Runtime /api/v1/onnx Any model in the ONNX open format (.onnx)
LLM Chat /api/v1/chat, /api/v1/models OpenAI-compatible chat completions and model list/retrieve

Quick Start

Docker

The fastest way to run SMILE Serve is via the pre-built Docker image. Mount a local directory containing your model files and map the port:

docker run -it \
  -v /path/to/model/folder:/model \
  -p 8888:8080 \
  ghcr.io/haifengl/smile-serve:latest

The service listens on port 8080 inside the container (8888 on the host). Place .sml and .onnx model files in the mounted folder; they are discovered automatically at startup.

Dev Mode

From the project root, start Quarkus live-reload dev mode (HTTP port defaults to 8888 in the %dev profile):

./gradlew :serve:quarkusDev \
  --jvm-args="--add-opens java.base/java.lang=ALL-UNNAMED"

The Quarkus Dev UI is available at localhost:8888/q/dev/. The React dev server runs on port 5173 and proxies API requests to the backend.

Packaging

Build a layered Quarkus application:

./gradlew :serve:build

java \
  --add-opens java.base/java.lang=ALL-UNNAMED \
  --add-opens java.base/java.nio=ALL-UNNAMED \
  --enable-native-access ALL-UNNAMED \
  -jar serve/build/quarkus-app/quarkus-run.jar

For a single uber-JAR or GraalVM native executable, see the full user guide.

Configuration

Configuration lives in serve/src/main/resources/application.properties. Override at runtime with -D system properties, for example:

java ... -Dsmile.serve.model=/data/models -jar quarkus-run.jar
Property Default Description
quarkus.http.port 8080 HTTP listen port (%dev default: 8888)
smile.serve.model ../model Path to a .sml file or directory of SMILE models
smile.onnx.model ../model Path to a .onnx file or directory of ONNX models
smile.chat.model ../model/Llama3.1-8B-Instruct Local Hugging Face checkpoint directory, or Hugging Face repo id
smile.chat.max-seq-len 0 (auto) Max context length (prompt + output); 0 uses model config
smile.chat.devices 0 CUDA device index, or comma-separated list for tensor parallelism

See the configuration reference for KV-cache, batching, memory fraction, and database settings.

Classic ML Inference

At startup, SMILE Serve scans smile.serve.model and loads every .sml file. Each model carries its trained algorithm, input feature schema, and optional metadata tags.

Model metadata

curl http://localhost:8080/api/v1/ml/models/iris_random_forest-1

Returns the algorithm name, input schema (field names and types), and tags. Use GET /api/v1/models to list all loaded model IDs.

Single inference

Send one sample as a flat JSON object whose keys match the model schema:

curl -X POST http://localhost:8080/api/v1/ml/models/iris_random_forest-1 \
  -H "Content-Type: application/json" \
  -d '{
    "sepallength": 5.1,
    "sepalwidth":  3.5,
    "petallength": 1.4,
    "petalwidth":  0.2
  }'

Response:

{
  "prediction": 0,
  "probabilities": [0.960, 0.021, 0.019]
}

Streaming inference

Process many samples via Server-Sent Events:

cat iris.csv | curl -X POST \
  -H "Content-Type: text/plain" \
  --data-binary @- \
  http://localhost:8080/api/v1/ml/models/iris_random_forest-1/stream

CSV rows follow the column order shown in the model schema (alphabetical by field name). JSON-lines mode (Content-Type: application/json) accepts one JSON object per line.

ONNX Inference

ONNX models are loaded from smile.onnx.model. The model ID is the file name without the .onnx extension. The ONNX Runtime native library must be on the OS library search path.

Model info

curl http://localhost:8080/api/v1/onnx/resnet50

Returns input/output tensor names, element types, and shapes (a -1 dimension is dynamic).

Single inference

curl -X POST http://localhost:8080/api/v1/onnx/my_classifier \
  -H "Content-Type: application/json" \
  -d '{"input": [1.0, 2.0, 3.0, 4.0]}'

The request body maps each input name to a flat JSON array of numbers. Streaming endpoints mirror the classic ML API (POST /api/v1/onnx/{id}/stream).

LLM Chat

SMILE Serve includes native Llama inference with an OpenAI-compatible chat API. If smile.chat.model is not available, chat endpoints return HTTP 503.

List models

curl http://localhost:8080/api/v1/models

Returns an OpenAI-compatible catalog of all loaded models — LLMs, ONNX graphs, and SMILE .sml models. Inference still uses type-specific paths.

Chat completions

curl http://localhost:8080/api/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{
    "model": "meta-llama/Llama-3.1-8B-Instruct",
    "messages": [{"role": "user", "content": "What is SMILE?"}],
    "stream": true
  }'

Set "stream": true for token-by-token Server-Sent Events output. Conversation history can be persisted when a database is configured — see below.

Tool calling (Qwen3+)

For Qwen3 / Qwen3.5 / Qwen3.8 models, pass OpenAI-style tools and receive finish_reason: "tool_calls" with structured message.tool_calls. Clients execute tools locally and continue with role: "tool" messages.

curl http://localhost:8080/api/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{
    "messages": [{"role": "user", "content": "Weather in SF?"}],
    "tools": [{
      "type": "function",
      "function": {
        "name": "get_current_temperature",
        "description": "Get temperature",
        "parameters": {
          "type": "object",
          "properties": {"location": {"type": "string"}},
          "required": ["location"]
        }
      }
    }],
    "tool_choice": "auto"
  }'

Web UI

A React web interface is bundled via Quarkus Quinoa and served from the root URL:

  • Inference UI (/infer) — sidebar lists chat, SMILE (.sml), and ONNX (.onnx) models. Selecting a chat model embeds the chat module in the right pane; SMILE models get a schema-driven form; ONNX models get a numeric or image-upload form.
  • Chat UI (/chat) — standalone chat with streaming tokens and Markdown/math rendering.

Database

Chat conversation history requires a relational database. ML and ONNX inference work without a database.

Profile Backend URL
Production PostgreSQL jdbc:postgresql://localhost:5432/smile
Dev SQLite jdbc:sqlite:./smile_serve.db
Test H2 (in-memory) jdbc:h2:mem:test

Enable ORM in production:

quarkus.hibernate-orm.active=true
quarkus.datasource.username=<user>
quarkus.datasource.password=<password>
